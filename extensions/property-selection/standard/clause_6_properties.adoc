[#rc_{req-class}]
== Requirements Class "Property Selection"

[cols="2,7",width="90%"]
|===
^|*Requirements Class* |http://www.opengis.net/spec/{standard}/{m_n}/req/{req-class} 
|Target type |Web API
|===

The Requirements Class "Property Selection" specifies the query parameters "properties" and "exclude-properties".

The query parameter "properties" takes a comma-separated list of property names that are to be included in the response. Properties where the name is not included in the query parameter value are in general not included in the response.

The query parameter "exclude-properties" takes a comma-separated list of property names that are to be omitted from the response. All other properties are included in the response. This is useful, if a resource has many properties and only a few of them are not needed, for example, a geometry with many coordinates.

The two query parameters cannot be combined in a request.

Clients cannot rely on the order of the property names in the value of the query parameter "properties" to determine the order of the properties in the response. If the media type of the response has a concept of property order, the server determines the order, for example, according to the keyword "x-ogc-propertySeq" in a schema of the returnables according to <<OAFeat-5,OGC API - Features - Part 5: Schemas>>.

An empty value of one of the query parameters is an empty list of property names. With `properties=`, no returnable property is selected, so the response only includes what the media type requires. With `exclude-properties=`, no property is excluded.

By default, that is, if a request includes neither of the two query parameters, all properties are included in the response. An API can change this by specifying a default value for one of the two query parameters in the API definition (but not for both), for example, to omit properties that are large or rarely needed, unless a client explicitly asks for them. The default value only applies, if a request includes neither of the two query parameters. For example, if the query parameter "exclude-properties" has a default value, a client can request all properties with `exclude-properties=`.

A property name that is not the name of a returnable property of the web resource results in an error. This helps clients to detect misspelled property names.

The query parameters can be applied to web resources that can be represented as an object with properties or to resources that are collections of such objects; for example, a collection of features, a single feature or a vector tile.

The list of valid property names can be determined from the API definition, if the schema of the query parameter lists them (see <<rec_properties_returnables-enum>>), or, if a schema of the returnables is available, from the JSON Schema according to <<OAFeat-5,OGC API - Features - Part 5: Schemas>>, Requirements Class "Returnables and Receivables".

:req: response
[#req_{req-class}_{req}]

|===
^|*Requirement {counter:req-num}* |/req/{req-class}/{req}
^|A | If a request includes neither the query parameter "properties" nor the query parameter "exclude-properties", all properties SHALL be returned or, if the API definition specifies a default value for one of the two query parameters, the properties according to that default value.
^|B | If the query parameter "properties" is provided, only the selected returnable properties included in the parameter value SHALL be returned, with the exception of properties that the media type of the response requires.
^|C | If the name of an object-valued property is selected, the complete object SHALL be returned. If properties inside an object-valued property are selected, only the selected properties of the object SHALL be returned.
|===

:req: exclusive-parameters
[#req_{req-class}_{req}]
[width="90%",cols="2,7a"]
|===
^|*Requirement {counter:req-num}* |/req/{req-class}/{req}
^|A | If a request includes both query parameters "properties" and "exclude-properties", the server SHALL respond with status code 400 (Bad Request).
^|B | The API definition SHALL NOT specify a default value for both query parameters "properties" and "exclude-properties" of a web resource.
|===

:req: unknown-properties
[#req_{req-class}_{req}]
[width="90%",cols="2,7a"]
|===
^|*Requirement {counter:req-num}* |/req/{req-class}/{req}
^|A | If the value of the query parameter "properties" or "exclude-properties" includes a property name that is not the name of a returnable property of the web resource, the server SHALL respond with status code 400 (Bad Request).
|===

The OpenAPI fragments of the query parameters "properties" and "exclude-properties" accept any property name, because the returnables differ between web resources. Without a list of the valid property names in the API definition, clients have to determine the valid values in another way, for example, from a schema of the returnables, if one is available. An API definition that describes the operations of each collection separately can list the returnables of the collection, which also allows tools to offer a selection of the valid property names. An API definition that describes the operations of all collections using a path parameter `collectionId` cannot do this.
